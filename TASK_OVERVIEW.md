# Freight rate assessment: requirements and initial findings

## Objective

Predict the `posted_rate` of a freight load using the supplied labeled data.
Choose and justify the exploration, cleaning, features, model, and validation
strategy. The brief does not give a numerical grading rubric or specify the
hidden evaluation metric.

## Required submission

1. An accessible GitHub repository with solution code, dependencies, and run instructions.
2. `validation_predictions.csv` with exactly `load_id,predicted_rate`, one
   finite positive prediction per supplied final ID, and exactly 12,000 rows.
3. Completed December predictions: Lexington to Fort Wayne, 360 miles,
   Dry Van, 32,000 lb, one row per day in December 2025. Keep the original
   seven-column schema; only fill `predicted_rate`.
4. A PDF or DOCX report describing the validation and split approach and
   containing `candidate_december.png` generated by the provided scorer.
5. A 2-3 minute Loom recording with camera on: exploration findings, data-quality
   issues and handling, model reasoning, training and validation split, and an
   important-code walkthrough. The candidate must record this.

The scorer does not evaluate accuracy locally. It validates both CSVs and
generates the chart; Spotter calculates final metrics after submission.

## Initial observations to investigate

- Training dates: January 1-October 31, 2025. Final prediction dates:
  November 1-December 31, 2025. Start with chronological validation that
  imitates future prediction; fit preprocessing only on each training split.
- Labeled data has 300 missing weights and 374 missing market indices.
  Final data has 165 missing weights and 249 missing market indices.
- Training contains 292 negative weights and the final set contains 145.
  Determine a defensible treatment
  through exploration; do not silently assume their intended values.
- No duplicate full rows or duplicate IDs were found in either main dataset.
- Training has 64 unique pickup cities and 64 delivery cities; the final set
  has 72 of each. Inspect unseen cities and generalization to unfamiliar lanes.
- The December chart input omits coordinates, `market_index`, and `quote_signal`.
  Define and validate an inference strategy for that reduced feature set.
- Audit the predictive signals for leakage and realistic inference availability.
- The supplied README paths differ from the actual root-level filenames.

## Proposed implementation sequence

1. Complete and verify the isolated Python environment (complete).
2. Perform reproducible data-quality and exploratory analysis (complete; see `reports/eda/exploration.md`).
3. Establish chronological holdouts, evaluation metrics, and simple baselines (complete).

5. Select the model using development results and retrain on eligible labeled data.
6. Generate both prediction files and run the original scorer.
7. Produce the report, repository instructions, and a concise Loom script.

Analysis can be rerun with `python -m freight.explore`; the development model
comparison runs with `python -m freight.benchmark`. Model selection, the reserved

by the candidate; commands for completed checkpoints are in `GIT_WORKFLOW.md`.
