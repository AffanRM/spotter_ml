### Data and leakage boundaries

- Labeled dates end October 31; final inputs start November 1. IDs are disjoint.
- Development backtests train January-April / validate May-June and train
  January-June / validate July-August. Candidate comparison uses these only.
- The final check trains on 38,477 January-August loads and scores all 9,523
  September-October loads. These labels are not used for fitting or early stopping.
- Dataset-level exploratory summaries included all development months. Therefore
  this is a reserved model-performance check, not an externally sequestered blind
  test. No model choices were changed after its performance was observed.
- The cleaner and feature builder do not learn from validation labels. Ridge's
  imputation/scaling/encoding and the equipment baseline fit on training rows.
  CatBoost learns only from the training features/labels passed to its fit call.
- The city stress test selects eight cities by target-independent stable hashes
  from the first training window and removes both pickup and delivery occurrences.
- Main inference excludes `load_id` and `posted_rate`. The chart path excludes
  all six unavailable coordinate/signal fields throughout fitting and inference.
- Missing/invalid weights retain indicators. Negative values are not silently
  converted to positive values. No validation loads or extreme labels are dropped.

iterations, depth 6, learning rate 0.05, L2 leaf regularization 5, seed 42, and
four threads. A separate chart-only model uses the same fixed hyperparameters.
The code and policy hashed in the original evaluation remain unchanged.

## Improvements made during this audit

1. **Reviewer portability.** Previously the submission command rejected another
   Python patch version even with identical evaluated data/code/policy. It now
   permits a new-environment refit while recording the generation environment
   separately and preserving the original holdout evidence. It still rejects
   changed evaluated inputs/code/policy and incompatible saved bundles.
2. **Accurate reload evidence.** Previously prediction-only generation always
   claimed in-memory-versus-reloaded verification, including bundles without a
   recorded check. Full refits now persist that verification result; reuse reports
   it only when the bundle contains the evidence. Regression tests cover the
   provenance distinction.
3. **Independent integrity command.** `python -m freight.audit
   --require-saved-models` checks prediction schemas/values, raw and output hashes,
   scorer integrity, frozen provenance, split separation, metric arithmetic,
   documentation links, model bundles, and every output prediction.
4. **Reviewer instructions.** The README now starts with purpose, results and a
   short fresh-clone workflow. Setup clarifies environment reproduction and
   removes stale statements from the environment-setup stage.
5. **Automated checks.** Added a read-only GitHub Actions workflow for Windows
   and Linux: locked install, dependency compatibility, unit tests, deliverable
   audit and employer scorer. Configuration follows the
   [official GitHub Python workflow documentation](https://docs.github.com/en/actions/tutorials/build-and-test-code/python).
   Hosted jobs have not run yet; their first run requires the candidate's push.

## Remaining risks and honest limits

- The hidden final labels and grading metric are unavailable. Local checks
  establish correctness and reproducibility, not guaranteed hiring marks.
- The quote signal changes relationship over time, and its generation and
  quote-time availability are undocumented. It is explicitly supplied as a final
  input; the chosen model uses it, with this risk documented.
- Geographic stress uses one fixed city subset. It is not a confidence interval
  for all possible unseen cities. Final inputs have 1,447 loads involving a new city.
- One partial calendar year does not identify yearly seasonality or holiday
  effects. The December plot is a conditional model prediction, not a calibrated
  forecast or prediction interval.
- No new tuning against the final check was introduced during review. Future
  modeling changes using those results would need a new validation account.
- The assignment does not require a web app, API server, or deployment. Those
  would add scope without satisfying an additional stated requirement.
